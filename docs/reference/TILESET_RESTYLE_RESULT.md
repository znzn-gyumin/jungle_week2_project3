# 타일셋 화풍 재작업 — 결과와 판단 근거

> **채택하지 않았습니다. `BASE`(현행) 를 그대로 씁니다.**
> 나중에 다시 볼 수 있도록 결과와 근거만 남깁니다.
>
> `soft` · `none` 은 **파일로 보관하지 않습니다** — [`tools/tilegen/style.py`](../../tools/tilegen/style.py)
> 가 저장소에 있어서 언제든 다시 만들 수 있습니다.
>
> ```bash
> JL_OUT=assets/temp/restyle/soft JL_STYLE=soft python -m tools.tilegen.build
> JL_OUT=assets/temp/restyle/soft JL_STYLE=soft python -m tools.tilegen.previews
> python tools/style_compare.py            # 비교 이미지 4장
> ```
>
> **`JL_STYLE` 기본값이 `hard` 라 환경변수를 안 주면 현행과 한 픽셀도 다르지 않습니다.**
> 타일셋·맵·인덱스 18개 파일이 md5 까지 같은 것을 확인했습니다.
>
> 비교 이미지 4장은 [`tileset_restyle/`](./tileset_restyle) 에 있습니다.
> 작업 지시서는 [TILESET_RESTYLE](./TILESET_RESTYLE.md) 입니다.

---

**현행 에셋은 한 글자도 안 건드렸습니다.** `assets/tilesets/` `assets/map/` `preview/` 모두 그대로입니다.

## 1. 무엇을 바꿨는가

### 새로 만든 것 — [`tools/tilegen/style.py`](../../tools/tilegen/style.py)

환경변수 `JL_STYLE` 하나로 `hard`(기본=현행) / `soft` / `none` 을 가릅니다.

```bash
JL_OUT=assets/temp/restyle/soft JL_STYLE=soft python -m tools.tilegen.build
JL_OUT=assets/temp/restyle/soft JL_STYLE=soft python -m tools.tilegen.previews
```

**환경변수를 안 주면 현행과 md5 가 같습니다.** 타일셋 3종 · 맵 7개 · 인덱스 전부 18개 파일을
`base/` 와 대조해 확인했습니다. 화풍을 바꾸느라 현행 빌드가 조용히 달라지는 일은 없습니다.

### 고친 것 — [`tools/tilegen/core.py`](../../tools/tilegen/core.py)

| 함수 | 무엇을 |
|---|---|
| `Canvas.outline` | `soft`: 고정 잉크색 `#2A2632` 대신 **이웃 8픽셀 평균색을 45% 어둡게 + 알파 185**. 물체 자기 색이라 선이 아니라 접촉 그늘로 읽히고, 반투명이라 바닥이 비칩니다. `none`: 바깥 팽창 자체를 생략 |
| `Canvas._inner_rim` *(신규)* | `none` 전용. 실루엣 **안쪽** 1px 을 22% 어둡게 — 선 대신 어두운 덩어리로 형태를 잡습니다. 캔버스 밖은 불투명으로 쳐서 벽·바닥 조각의 네 변이 어두워지지 않게 했습니다 |
| `Canvas._contact_shadow` *(신규)* | `none` 전용. 발밑 2px 접지 그림자(알파 85 / 40). 외곽선을 지우면 오브젝트가 바닥에서 뜹니다 |
| `shade_regions` *(신규)* | 단색 덩어리마다 세로 밝기 램프. 평면 채움이 팔레트 스냅을 거치며 **2~3단 계조**로 떨어집니다 |
| `Piece.render` | 위 후처리 호출 |
| `snap_palette` | `alpha_levels` 인자 추가 — 0/255 이진화 대신 `(0,60,120,185,255)` 로 양자화해 반투명 외곽선과 접지 그림자를 살립니다 |
| `expand_palette` *(신규)* | 팔레트 각 색에 ±9% ±18% 명암 단계를 파생 |
| `TilesetBuilder.atlas` | 조각별로 스냅. **바닥(`f_*`) 만 원본 팔레트** |

### 안 고친 것

* [`palettes.py`](../../tools/tilegen/palettes.py) — **값을 하나도 안 바꿨습니다.** 색조는 캠퍼스 사진에서 뽑은 것이라 유지하고, `expand_palette` 로 밝기 폭만 넓혔습니다. 색이 늘어도 '없던 색' 이 생기지는 않습니다
* `tiles_edu/dorm/out.py` 108+60+120 개 조각 — 한 줄도 안 건드렸습니다. 공통 코드만으로 세 타일셋이 같이 바뀝니다
* `maps.py`, `qa.py` — 문서가 건드리지 말라고 한 그대로

### 도중에 잡은 문제 — 바닥에 48px 얼룩

팔레트를 넓히자마자 **복도 바닥에 타일 크기 얼룩**이 생겼습니다.
지금까지 같은 색으로 뭉개지던 바닥 변형(`f_vinyl_a` / `f_vinyl_b`, `f_carpet_a/b/c`)이
넓어진 팔레트에서 서로 다른 색으로 갈라진 탓입니다.

바닥은 애초에 노이즈 텍스처라 계조를 넣을 이유가 없고, 이음매 위험만 큽니다. 그래서

* `shade_regions` 는 이름이 `f_` 로 시작하면 건너뛰고
* `atlas` 는 바닥 조각만 **원본 팔레트**로 스냅합니다

결과: **세 안의 바닥 타일 29개가 base 와 바이트 단위로 동일**합니다. 이음매 지표도 그대로입니다.


### 읽는 법

| 항목 | 목표 | 결과 |
|---|---|---|
| **색 수** | 문서 2절 「96~160색」 | **27~32 → 117~145.** 구간 안 |
| **2×2 단색 비율** | 도트 0.0~0.5% | 69~73% → **47~56%.** 방향은 맞지만 도트 근처엔 못 갑니다 — 48px 격자에 코드로 찍는 한 구조적 한계입니다(아래 4절) |
| **명도·채도** | 문서 2절 「맞추지 마세요」 | **유지.** 명도 68~70 → 67~69, 채도 16~20 → 15~20. 인물이 배경에 묻히는 일은 없습니다 |
| **외곽선 비율** | 문서 2절 「비율이 아니라 형태」 | 4.7~6.7% → 0.2~3.4%. 잉크선을 없앤 결과이지 도트의 20~80% 를 쫓아간 게 아닙니다 |

## 3. `qa.py` 결과

```bash
JL_OUT=assets/temp/restyle/<안> python -m tools.tilegen.qa
```

**세 안 모두 `== 문제 없음 ==`.** base 출력과 diff 를 떠서 **타일셋 3줄 말고는 완전히 동일**함을 확인했습니다.

| | base | soft | none |
|---|---|---|---|
| 통행=도달 (m1~m7) | 753·770·901·865·1138·914·1136 | 동일 | 동일 |
| 격자 정합 · 타일 수 | 103 / 52 / 112 | 동일 | 동일 |
| 최악 이음매 | f_rug 2.8 · f_gym 1.19 · f_grass_b 1.2 | 동일 | 동일 |
| 여명 색상 · M1/M5 설계 검사 | 통과 | 통과 | 통과 |
| `colors` | 32 / 27 / 30 | 142 / 117 / 133 | 145 / 121 / 138 |
| `outline_ratio` | .051 / .061 / .090 | .110 / .058 / .080 | .108 / .065 / .085 |

### 문서 예상과 실제가 다른 점 두 가지

**① 색 수와 외곽선 비율은 `qa.py` 에서 "걸리지" 않습니다.**
문서 6절은 이 둘이 걸릴 수 있다고 했지만, `qa.py` 는 이 두 값을 **판정에 쓰지 않고 보고만 합니다**
(`check_tilesets` 는 `issues` 에 아무것도 넣지 않습니다). 기준선을 옮길지 말지를 코드가 강제하지 않으므로,
문서 6절의 그 문장은 **사실과 다릅니다** — 채택하면 같이 고쳐야 합니다.

**② `outline_ratio` 가 내려가는 게 아니라 올라갔습니다** (edu .051 → .110).
`qa.py` 의 정의는 `sum(rgb) < 190` 인 **아주 어두운 픽셀 비율**입니다. 잉크선은 없앴지만,
면 계조가 원래 어둡던 덩어리(네이비 모니터·짙은 회색 의자·운동기구 고무)의 아랫부분을
그 문턱 아래로 더 내려보냅니다. `style_check.py` 는 같은 항목을 HSV 명도 0.22 로 재서 **내려갔다**고 나옵니다.
**두 지표가 서로 다른 것을 재고 있습니다** — 어느 쪽이든 "잉크선 밀도"를 재지는 못합니다.

## 4. 렌더 필터 — **NEAREST 유지. 바꿀 필요 없습니다**

문서 2절이 남긴 숙제("타일이 안티에일리어싱을 갖게 되면 NEAREST 확대에서 지저분해진다")에 대한 답입니다.

근거는 `tileset_restyle/cmp_zoom_filter.jpg` (8배 확대, 세 안 × NEAREST/LINEAR).

**전제가 성립하지 않습니다.** 이번 변경은 안티에일리어싱을 넣지 않았습니다.

* 계조는 **연속이 아니라 밴딩**입니다 — 팔레트 스냅이 여전히 마지막에 걸려서 모든 픽셀이 팔레트 색입니다
* 반투명 외곽선은 AA 가 아니라 **알파 5단 양자화**입니다. 확대해도 픽셀 경계가 뭉개지지 않고, 바닥과 합성될 때만 어두워집니다
* 2×2 단색 비율이 47~56% 로 남아 있는 것 자체가 격자 정합이 살아 있다는 증거입니다

확대 이미지에서 `soft/NEAREST` 는 base 만큼 또렷하고, `LINEAR` 쪽은 **바닥 카펫 노이즈까지 뭉개져서 세 안 모두 나빠집니다.**
[`assets/README`](../../assets/README.md#도트는-진짜-픽셀-아트가-아닙니다) 의 타일=NEAREST / 도트=LINEAR 분리는 **그대로 두는 게 맞습니다.**

### 다만 새로 생긴 조건 하나

반투명 픽셀이 처음으로 타일셋에 들어갑니다. 오브젝트 레이어의 부드러운 외곽선은 **아래 바닥 타일과 알파 합성**되어야 제 색이 납니다.
Phaser 타일맵 기본 동작이라 따로 할 일은 없지만, **바닥 타일이 없는 칸에 오브젝트를 놓으면** 그 가장자리가
배경색과 섞입니다. 현재 맵 7개에는 그런 칸이 없습니다.

## 6. 채택하면 해야 할 일

1. `JL_STYLE=soft` 로 `JL_OUT` 없이 빌드 → `assets/tilesets/` `assets/map/` `preview/` 갱신
2. [`assets/README`](../../assets/README.md#도트는-진짜-픽셀-아트가-아닙니다) — "27~32색 팔레트 스냅" 서술과 "붕 뜨지 않습니다" 판단 문단 수정. **NEAREST/LINEAR 표는 그대로**
3. [`TILESET_MAP_HANDOFF`](./TILESET_MAP_HANDOFF.md) — 색 수 수치
4. [`TILESET_RESTYLE`](./TILESET_RESTYLE.md) 6절 — 위 3절 ① 의 사실 오류
5. `style.py` 의 기본값을 `soft` 로 옮길지 결정 (옮기면 `hard` 가 A/B 용으로 남습니다)
