# jungLover — 타일셋 화풍을 도트 인물에 맞추기

**타일셋 3종을 [`assets/dot/walk/`](../../assets/dot/walk) 의 화풍으로 다시 그리는 작업**입니다. 결과물은 **`assets/temp/restyle/` 에만** 쌓고 현행 에셋은 건드리지 않습니다.

현재 상태는 [TILESET_MAP_HANDOFF](./TILESET_MAP_HANDOFF.md)가 정본입니다. 이 문서는 **바꾸는 방법**만 다룹니다.

---

## 0. 먼저 알아야 할 것 — 지금 대비는 "의도된 것"이라고 적혀 있습니다

[`assets/README`](../../assets/README.md#도트는-진짜-픽셀-아트가-아닙니다)에 이렇게 남아 있습니다.

> **M1 위에 얹어 확인했습니다.** 타일이 20색 저채도라 인물이 눈에 먼저 들어오는데, 배경이 조용하고 캐릭터가 도드라지는 건 VN·RPG에서 정상입니다. 붕 뜨지 않습니다.

**이 작업은 그 판단을 뒤집는 시도입니다.** 그러니 결과를 현행과 나란히 놓고 비교할 수 있어야 하고, 그래서 `assets/temp/` 에만 씁니다. 채택 여부는 눈으로 보고 정합니다.

## 1. 두 화풍이 실제로 얼마나 다른가

측정값입니다(불투명 픽셀 기준). `python tools/style_check.py` 로 언제든 다시 잽니다.

| | 도트 18종 | 타일셋 3종 | |
|---|---|---|---|
| **색 수** | 3,920 ~ 14,184 | **27 ~ 32** | 두 자릿수와 네 자릿수 |
| **2×2 블록이 단색인 비율** | **0.0 ~ 0.5%** | 69 ~ 73% | 타일은 격자에 딱 맞고, 도트는 전혀 안 맞음 |
| **어두운 픽셀 비율** (명도 <0.22) | 20 ~ 80% | 4.7 ~ 6.7% | 도트는 외곽선이 아니라 **어두운 덩어리**로 형태를 잡음 |
| 평균 명도 | 18 ~ 61% | 68 ~ 70% | ↓ 2절 주의 |
| 평균 채도 | 7.6 ~ 56% | 16 ~ 20% | 도트 쪽 편차가 큽니다 — 인물마다 옷 색이 달라서입니다 |

**도트 쪽 편차가 큰 항목(외곽선·명도·채도)은 화풍이 아니라 의상 차이**입니다. 검은 후드(민아 80%)와 밝은 셔츠(모브 39%)가 같은 화풍인데 수치가 두 배 벌어집니다. **화풍을 가리키는 건 위 두 줄** — 색 수와 2×2 단색 비율입니다.

눈으로 보면 이렇게 갈립니다.

| | 도트 인물 | 타일셋 |
|---|---|---|
| 경계 | 색이 서서히 바뀌며 끝남. **외곽선이 따로 없음** | **1px 하드 아웃라인** `#2A2632` |
| 면 | 부드러운 그라데이션. 머리카락에 하이라이트가 흐름 | 평면 채움 + 밝은 띠 한 줄 |
| 정합 | 픽셀 격자에 안 맞음 (축소된 일러스트) | 격자에 정확히 맞음 (코드로 찍음) |
| 인상 | 손으로 그린 것 | 도면으로 그린 것 |

## 2. 무엇을 맞추고 무엇을 두는가

### 맞출 것

1. **외곽선을 없애거나 부드럽게** — 지금 `core.py` 가 실루엣 알파를 1px 팽창시켜 `#2A2632` 로 두릅니다. 도트에는 그런 선이 없습니다. **가장 큰 차이고 가장 먼저 손댈 곳입니다.**
2. **면에 계조를 넣기** — 평면 + 하이라이트 한 줄 대신 2~3단 그라데이션.
3. **팔레트 스냅 완화** — 27~32색이 "코드로 그린 것" 인상의 절반입니다. 96~160색 정도로 늘리거나, 스냅 대신 디더 없는 근사로 바꿉니다.

### 두어야 할 것 — 맞추면 오히려 나빠집니다

**평균 명도·채도·외곽선 비율은 맞추지 마세요.** 위에서 봤듯 이 셋은 인물 의상이 만든 값입니다. 배경 타일을 민아의 검은 후드(명도 18%)에 맞추면 **인물이 배경에 묻힙니다.** 지금 68~70%를 유지하고 화풍만 바꿉니다.

**외곽선은 "비율"이 아니라 "형태"를 바꾸는 것**입니다. 도트에 어두운 픽셀이 많은 건 옷이 검어서지 선을 둘러서가 아닙니다. 타일에서 없앨 것은 **1px 하드 아웃라인이라는 형태**이고, 어두운 픽셀 비율을 20%까지 올리라는 뜻이 전혀 아닙니다.

### 판단이 필요한 것

**렌더 필터가 따라 바뀝니다.** [`assets/README`](../../assets/README.md#도트는-진짜-픽셀-아트가-아닙니다)가 타일은 `NEAREST`, 도트는 `LINEAR` 로 갈라 두었습니다. 타일이 안티에일리어싱을 갖게 되면 `NEAREST` 확대에서 흐린 픽셀이 각져 지저분해집니다 — 타일도 `LINEAR` 로 옮겨야 할 수 있습니다. **결과를 확대해서 확인하고 문서에 결론을 적어주세요.**

## 3. 절대 깨면 안 되는 것

맵 7개가 타일셋을 **조각 이름과 타일 id 로** 참조합니다. 여기가 어긋나면 맵이 통째로 무너집니다.

| | 왜 |
|---|---|
| **48px 격자** | `TS = 48`. 맵 좌표 전부가 이 값을 씁니다 |
| **조각 이름** | `.index.json` 의 `pieces` — `maps.py` 가 `m.place(E, "desk_monitor", ...)` 처럼 이름으로 부릅니다. 이름을 지우거나 바꾸면 맵 생성이 죽습니다 |
| **타일 수와 순서** | 맵 JSON 에 gid 가 박혀 있습니다. `firstgid + 인덱스` 로 찾으므로 **순서가 바뀌면 다른 가구가 나옵니다** |
| **`solid` 정의** | 각 조각의 충돌 칸. 바꾸면 통행 가능 칸 수가 변하고 `qa.py` 의 도달 검사가 깨집니다 |
| **타일셋 이름 3종** | `tileset_edu_indoor` `tileset_dorm_indoor` `tileset_outdoor` |

**조각을 새로 추가하는 건 괜찮습니다** — 뒤에 붙으면 기존 gid 가 안 밀립니다.

## 4. 어디를 손대는가

```
tools/tilegen/
├─ core.py          344줄  Canvas · TilesetBuilder · 외곽선 팽창 ← 여기가 화풍의 심장
├─ palettes.py       75줄  EDU / DORM / OUT 팔레트 + 스냅
├─ tiles_edu.py     712줄  교육동 조각 108개
├─ tiles_dorm.py    401줄  숙소동 조각 60개
├─ tiles_out.py     624줄  야외 조각 120개
├─ build.py          93줄  전체 빌드 진입점
├─ render.py        190줄  맵 → 미리보기 PNG
├─ previews.py      102줄  프리뷰 시트
└─ qa.py            487줄  자동 검수 ← 손대지 마세요
```

**`core.py` 와 `palettes.py` 를 먼저 읽으세요.** 조각 파일 셋을 다 고치기 전에, 외곽선·계조·스냅을 다루는 공통 코드만 바꿔도 세 타일셋이 한꺼번에 달라집니다. 조각별 손질은 그 다음입니다.

`maps.py` 는 **건드리지 마세요.** 배치는 이 작업의 범위가 아닙니다.

## 5. 임시 폴더로 출력하기

생성기가 `JL_OUT` 환경변수를 봅니다([`paths.py`](../../tools/tilegen/paths.py)). 이것만 지정하면 **현행 에셋에 한 글자도 안 닿습니다.**

```bash
JL_OUT=assets/temp/restyle python -m tools.tilegen.build
JL_OUT=assets/temp/restyle python -m tools.tilegen.previews
```

빌드와 프리뷰는 **명령이 따로**입니다. 이렇게 쌓입니다.

```
assets/temp/restyle/
├─ assets/tilesets/    새 타일셋 3종 + .tsj + .index.json   (18 파일)
├─ assets/map/         새 맵 7개 (타일셋이 임베드되므로 같이 나옵니다)
└─ preview/            맵 7장 · 조명 5종 · 이음매 검사 · 시트  (20 파일)
```

**아무것도 고치기 전에 한 번 돌려 두세요.** 현행과 똑같은 결과가 나오고, 그게 비교 기준선이 됩니다.

> **`pip install -r tools/requirements.txt`** — 조명 프리뷰와 여명 검사가 `numpy` 를, 전부가 `Pillow` 를 씁니다.

`assets/temp/` 는 **배포에서 제외되고 git 추적도 안 됩니다**(`.gitignore`, `vite.config.ts`). 개발 서버에서는 `/assets/temp/...` 로 읽히므로 브라우저로 바로 볼 수 있습니다.

## 6. 검수

### 자동

```bash
JL_OUT=assets/temp/restyle python -m tools.tilegen.qa
```

`qa.py` 가 **격자 정합 · 타일 수 · 색 수 · 외곽선 비율 · 이음매 · 맵 도달성 · 설계 의도 · 여명 색상**을 봅니다. 현행 기준선은 이렇습니다 — 교육동 103타일 32색 외곽선 5.1%, 숙소동 52타일 27색 6.1%, 야외 112타일 30색 9.0%. 화풍을 바꾸면 **색 수와 외곽선 비율 항목이 걸릴 수 있는데, 그건 이 작업이 의도한 것**입니다. 걸린 항목과 새 값을 적어주세요 — 기준선을 옮길지는 그때 정합니다.

**나머지 항목이 하나라도 깨지면 되돌려야 합니다.** 특히 맵 도달성과 통행 칸 수는 화풍과 무관해야 합니다.

| 맵 | 통행 = 도달 |
|---|---|
| m1 753 · m2 770 · m3 901 · m4 865 · m5 1,138 · m6 914 · m7 1,136 | 이 값이 변하면 `solid` 를 건드린 것입니다 |

### 눈으로

**인물을 얹지 않고 판단하면 안 됩니다.** 이 작업의 목적 자체가 "인물과 배경이 같은 그림으로 보이는가" 입니다.

1. `assets/temp/restyle/preview/` 의 맵 이미지를 열고
2. 같은 자리에 [`assets/dot/walk/minah.webp`](../../assets/dot/walk/minah.webp) 의 한 프레임(48×64)을 얹어
3. **현행 타일셋으로 만든 [`preview/`](../../preview) 의 같은 맵과 나란히** 놓고 비교합니다

밝은 맵(m1 낮)과 어두운 맵(m5 심야) 양쪽에서 봐야 합니다 — 조명 오버레이가 화풍 차이를 키우거나 덮습니다.

## 7. 끝나면 남길 것

`assets/temp/restyle/NOTES.md` 에 이 셋만 적어주세요.

1. **무엇을 바꿨는가** — `core.py` 의 어느 함수, `palettes.py` 의 어느 값
2. **측정값이 어떻게 변했는가** — `python tools/style_check.py assets/temp/restyle` 출력 그대로
3. **`qa.py` 에서 걸린 항목**과 그게 의도인지 아닌지

채택이 결정되면 그때 `assets/tilesets/` 로 옮기고, `TILESET_MAP_HANDOFF` 의 수치와 `assets/README` 의 화풍 서술을 함께 고칩니다.
